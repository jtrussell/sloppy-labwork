Overview

The shared visual language for Sloppy Labwork: design tokens, element defaults, components, and the rules for combining them. KeyChain has its own styles and is not covered here.

Use the theme buttons above to preview any page in each of the four themes. Examples marked with theme frames render every theme side by side.

Principles

  1. Tokens, not values. Colors, spacing, type, radius, shadow and motion come from tokens.css. Hex, rgb and named colors never appear outside it.
  2. Semantic over literal. Use --color-danger, not "red"; --color-surface, not "a slightly lighter purple".
  3. Components own their insides, not their surroundings. A component sets its padding and internal gaps; the parent decides the space around it with gap.
  4. Every theme, every time. Anything new is checked in all four themes before it ships.
  5. Consistency over novelty. Reach for an existing component or token before inventing a new one; extend the system here when something is genuinely missing.

Stylesheet architecture

Pages load a single entry point, static/css/site.css, which assigns each global stylesheet to a cascade layer:

LayerFileContains
resetvendor/…/normalize.cssBrowser normalization
unlayeredfonts.cssRaleway @font-face rules
unlayeredtokens.cssCustom properties and themes
basebase.cssElement defaults and typography
componentscomponents.cssLayout primitives and components
utilitiesutilities.cssSingle-purpose helpers
unlayered<app>/main.cssApp-specific layout and styles

Later layers always win over earlier ones regardless of selector specificity, and unlayered app stylesheets win over every layer. An app can therefore adjust a component with a plain class selector — no !important or selector stacking.
