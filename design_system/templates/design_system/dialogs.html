Dialog

Every dialog is a native <dialog class="dialog">. The browser handles focus trapping, Escape, the backdrop and stacking; js/dialog.js adds open and close triggers, backdrop clicks, scroll lock and the htmx wiring.

htmx-loaded dialogs

Pages include one empty host, components/dialog-host.html (<dialog id="dialog" data-dialog-remote>). Target it with the default innerHTML swap to load a dialog from the server; it opens when content arrives and empties when it closes. Partials use title_id="dialog-title" so the host stays labelled.

Confirm

Pages include components/dialog-confirm.html once. Any htmx element with hx-confirm then asks through it. The question renders as plain text, and Cancel has focus so pressing Enter never confirms by accident.

{% verbatim %}<button hx-post="{% url 'lineups-note-delete' note.id %}" hx-confirm="Delete this note?">Delete</button>{% endverbatim %}
{% ds_example no_markup %}
{% end_ds_example %}

Scripts can ask the same question with window.sloppyConfirm(question), which resolves to true or false.

Guidelines

  • Give every dialog aria-labelledby pointing at its title.
  • Put autofocus on the element that should receive focus: the first field, or the title via focus_title=True.
  • Use a dialog for a short, focused task. Long or multi-step work belongs on its own page.
  • Don't open a dialog from page load.
  • Dialogs fade their backdrop in and rise into place with a slight overshoot (--duration-enter, --ease-bounce), then fade out faster on close (--duration-exit). Reduced-motion users get the fade without movement. Tune per dialog with --dialog-hidden-transform.
