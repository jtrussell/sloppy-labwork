How themes are applied

A player's theme is stored on their profile and rendered as data-theme on <html>. Each theme is a block in tokens.css that redefines the themeable tokens; everything else reads those tokens and follows along.

{% for value, label in themes %} {% endfor %}
data-themeTheme
{{ value }}{{ label }}

Because theme blocks match [data-theme] on any element, a theme can be scoped to part of a page — that's how the side-by-side examples in this gallery work. A scoped region needs its own background; its text color follows the theme automatically.

Rules

  1. Components reference semantic tokens only. No hex, rgb or named colors outside tokens.css.
  2. Tints are mixed with color-mix() from a semantic token or currentColor using --tint-subtle / --tint-strong.
  3. Every theme block defines the complete themeable set — color, tint, link and shadow tokens. A test in design_system/tests.py enforces this.
  4. Tokens built from other themeable tokens go in the derived block at the end of tokens.css, so they recompute inside each theme scope.
  5. Contrast themes underline links and drop tints to 0%; state must be readable from borders and text alone.
  6. Every page shell sets data-theme and loads site.css.

Adding a theme

  1. Add a choice to UserProfile.ThemeOptions.
  2. Copy an existing [data-theme="N"] block in tokens.css with the new number and set every value.
  3. Check text, muted text and status colors against --color-bg and --color-surface (4.5:1 for text).
  4. Run the design system tests and review every gallery page in the new theme.
